What is CSRF?

Cross-Site Request Forgery (CSRF) is an attack that tricks a user's browser into submitting a malicious request to a site where the user is authenticated. Because browsers automatically attach cookies (including session cookies), the server cannot distinguish between a legitimate form submission and a forged one — unless a CSRF token is used.

CSRF vs CORS

Aspect CSRF CORS
Purpose Prevent forged requests from tricking the server Control which origins can read responses
Mechanism Unique token per session/request HTTP headers (Origin, Access-Control-*)
When needed Cookie/session-based auth + HTML forms Cross-origin API calls from browsers
This project Disabled for /api/** (JWT); enabled here Configured in SecurityConfig for allowed origins

How This Project Handles CSRF

SecurityConfig.java configuration: 
.csrf(csrf -> csrf
    .ignoringRequestMatchers("/api/**", "/graphql")  // Disabled for JWT APIs
    .csrfTokenRepository(CookieCsrfTokenRepository.withHttpOnlyFalse())  // Enabled for forms
)
  • /api/** and /graphql — CSRF disabled (stateless JWT, no cookies)
  • /csrf-demo — CSRF enabled (this page demonstrates it)
  • Token stored in a cookie (XSRF-TOKEN) for SPA compatibility
  • Thymeleaf injects the token automatically via th:action
